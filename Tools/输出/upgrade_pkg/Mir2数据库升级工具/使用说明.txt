Mir2 数据库升级工具（v111 版  更新日期 2026-11-12）
=========================================================

一、这个工具做什么
---------------------------------------------------------
把服务端目录里的两个库原地升级到当前版本，人物数据一个不删：
    Server.MirDB   物品/怪物/地图/NPC/任务库
    Server.MirADB  账号/角色/英雄库

本次（11-12）除了常规的版本升级，还多了一项「数据编码迁移」：

    羽化登仙的 BUFF 从「占用自定义槽位」改成了「专用枚举」
        旧：230(Custom1) = 羽化标记，232~241(Custom3~12) = 一重~十重
        新：159 = 羽化登仙标记，160~169 = 羽化一重~十重

    二进制布局没变，所以版本号还是 v111；老库能直接读，服务端启动时也会自动迁移。
    但迁移只发生在「读进来之后」，如果想把老库提前整理干净、并且留一份可回滚的备份，
    就用这个工具跑一遍。


二、怎么用（推荐）
---------------------------------------------------------
1. 关闭服务端（工具也会检查，进程在跑就拒绝执行）
2. 双击 Mir2DbUpgrade.exe
3. 选服务端目录（里面要有 Server.MirDB / Server.MirADB）
4. 点「预检」——只读，不改任何文件，先看看数据规模和羽化角色清单
5. 点「升级」

工具会自动：
    · 把两个库完整备份到 <服务端目录>\Back Up\dbupgrade-年月日_时分\（并校验 MD5）
    · 原地重写两个库（羽化 BUFF 的旧编码在这一步被改写成 159~169）
    · 重新加载，把升级前后的每一行数据逐条比对
    · 一旦比对不一致，自动从备份还原，不留半新半旧的档

如果版本号已是最新、羽化编码也已经是新的，工具会提示「无需升级」并且一个字节都不改。


三、命令行（可以写进批处理）
---------------------------------------------------------
    Mir2DbUpgrade.exe --check <服务端目录>    只读预检
    Mir2DbUpgrade.exe --auto  <服务端目录>    一键升级（失败自动还原）

返回码：0 = 成功/无需升级，1 = 失败，2 = 服务端在运行。


四、注意事项
---------------------------------------------------------
1. 升级完成后必须使用配套的新服务端（Shared.dll / Server.Library.dll 一起换）。
   库里现在是新编码 159~169，旧服务端不认识这些 BUFF 类型。
2. 备份不要删。回滚方式：工具里点「回滚到备份」，或手动把备份目录里的两个文件
   复制回服务端目录。
3. 工具只动这两个库文件，不碰 Configs、不碰地图、不碰脚本。
4. 羽化装备的限制是服务端行为：未登仙的角色不能「新穿」羽化专属盔甲/武器
   （Shape 1001~ / 2001~），已经穿在身上的不会自动扒下来——想退回未登仙，
   先用 NPC 命令 RESETHUMUP（会自动要求先脱装备）。


五、本次随包文件
---------------------------------------------------------
    Mir2DbUpgrade.exe / .dll / .deps.json / .runtimeconfig.json
    Server.Library.dll   与最新服务端一致
    Shared.dll           与最新服务端一致（含 159~169 枚举）
    log4net.dll

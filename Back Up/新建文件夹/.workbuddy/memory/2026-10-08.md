## 五次返工：修复「召唤不出来」——Frame 永久卡死

- 用户反馈：上一版（无条件排队）导致三个召唤技能都召唤不出宠物。
- **根因**：`SetAction()` 用 `Frames.TryGetValue(CurrentAction, out Frame)`，
  取不到时 `Frame` 被置为 **null**；而 `ProcessFrames()` 第一行就是
  `if (Frame == null) return;` —— 这是唯一还能再次触发 SetAction 的入口，
  于是对象**永久停在 Frame == null**：不绘制也不推进，表现为宠物根本不出现。
- 上一版的错：无条件排队。图库尚未就绪（微端重建数组后 _frames 为空）时排队 →
  取帧失败 → Frame = null → 卡死。
- **本次修复**（只改 Client/MirObjects/MonsterObject.cs）：
  1. 「召唤初现」排队从 Load 的第一个 switch 移到 **Frames 赋值之后**，
     并加 `Frames != null && Frames.ContainsKey(MirAction.召唤初现)` 前置判断 ——
     图库确实有这段动作才排队，绝不制造 Frame = null；图库没就绪就跳过，下次封包再判断。
  2. `ProcessFrames()` 开头补恢复路径：Frame 为 null 时先 `SetAction()` 重试，
     仍为 null 才 return。保证任何情况下都能退回站立动作、不会永久不显示。
  3. 月灵出场绘制索引修正：原代码写死 `224 + FrameIndex * 10`，实测 172.Lib 动作27
     是帧458-467（count=10 skip=-10），改为 `458 + FrameIndex`。
- 部署：Client.dll MD5 1b8b247ceeab46919dc9e0750e175453，两端一致，
  备份 *.20261008_1432.bak。**用户确认可召唤的版本 = Client.dll.20261008_1425.bak（14:11:26）**。
- 排错中确认的环境事实：DataPath 是相对路径 .\Data\，Monster 数组按本地最大编号 429 建，
  Monsters[170] 不越界；Process() 对 Frame==null 是容错的（置 DrawFrame=0），
  真正卡死点只在 ProcessFrames 那一行 return。

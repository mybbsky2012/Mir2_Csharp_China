## 毒符互换：修复「一用施毒术就疯狂换黄毒/灰毒」
- 用户反馈：「黄毒和灰毒不要一直疯狂的切换，第一次使用用毒的技能换黄毒，第二次使用用毒的技能再换灰毒 不要一用需要毒的技能就疯狂的换灰毒、绿毒」。
- **重要事实（从服务端 DB 实测得到）**：`E:\BaiduNetdiskDownload\韩Mir2\20260915更新\20260915Mir2Server\Server.MirDB`（文件，不是目录）里 `ItemType.护身符` 的 Shape 是：
  * Shape 0 = 护身符（符）
  * Shape 1 = **灰色毒粉**（小/中/大/特）→ 服务端 `PoisonType.Green`（持续掉血）
  * Shape 2 = **黄色毒粉**（小/中/大/特）→ 服务端 `PoisonType.Red`（削弱防御）
  验证方式：`Shared/Data/ItemData.cs` 的 ItemInfo 读取顺序是 Index(int32)+Name(string)+Type/Grade/RequiredType/RequiredClass/RequiredGender/Set(各1字节)+**Shape(int16)**，用 `tools/probe_itemdb.py` 在 DB 里定位名字后读后 6+2 字节即可。**注意：用户口中的「黄毒/灰毒」= Shape2/Shape1，代码注释里旧称「红毒/绿毒」容易叫错。**
- **疯狂互切的根因**（`Client/MirScenes/GameScene.cs` 手动施法链路）：
  `AutoPlayPrepareManualSpell` 是「先重算材料 → 再判断是否同一件物品」。当目标不缺毒/没目标时，材料由 `_autoPoisonNextShape` 交替决定；而**换装成功时就把指针翻转了**。于是 `AutoPlayRetryManualSpell` 补放时回调 `UseSpell` → 再次进入 prepare → 重算得到**另一种颜色** → `_manualSpellWant != load` 判定不成立 → 立刻又发一次换装 → 指针再翻回来 …… 每 ~120ms 翻一次，黄→灰→黄→灰 无限循环（聊天窗/装备槽看得见疯狂跳动）。目标已中毒、或没有目标时必现。
- **修法**：
  1. 新增 `_manualSpellCasting`：补放重入 `UseSpell` 时 prepare 直接 `return false` 放行，不再重判材料。
  2. 把「等待换装」的判定**提到重算材料之前**：`_manualSpellKey != 0 && CMain.Time <= _manualSpellUntil` 时，同一技能键或同为施毒术 → 直接 `return true` 继续等；换了别的技能才放弃等待。
  3. 交替语义改成「**一次使用交替一次**」：新增 `AutoPlayNextPoisonShape()`（取本次该用的毒粉）与 `AutoPlayUsePoisonShape(shape)`（把下一次换成另一种）。只在「槽里材料已就位、即将施放」或「补放的那一刻」才调用 `AutoPlayUsePoisonShape`，**不在发换装包时翻转**。
  4. `_autoPoisonNextShape` 初值 1 → **2**（第一次用施毒术装**黄色毒粉**，之后 黄→灰→黄…）；换角色/重登时重置为 2（手动与自动两条路都做）。
  5. 文案与注释全面改用真实物品名：灰色毒粉(绿毒, Shape1) / 黄色毒粉(红毒, Shape2)；面板提示语、文档 2.13 同步。
- 结果：第 1 次施毒术 = 黄色毒粉，第 2 次 = 灰色毒粉，依次交替；一次技能操作只换一次装；目标缺哪种毒时优先补哪种（交替指针同样只前进一次）。

## 全屏退出进程驻留——成因分析（19:19）
- 退出链：退出按钮 → Program.Form.Close() → CMain_FormClosing()（Settings.Save + DXManager.Dispose + SoundManager.Dispose）→ 窗体销毁 → Application.Run 返回 / 启动器 Closed → AMain_FormClosed → Environment.Exit(0)

### 一、拿真实物品库反查，发现并修掉 3 个「一眼假 / 功能性」缺陷

1. **装备筛选太「贪」→ 会挑到 GM/活动装（已修）**

   - 修法：签名从 `FindPotion(bool both)` 改成 `FindPotion(bool needHP, bool needMP)`；缺什么才允许返回什么（`needHP && hp <= 0 → continue`）；血权重要高（`value = hp*(needHP?2:0) + mp*(needMP?1:0)`）。

3. **自动喝药没防「缓回药连灌」（已修）**
   - 本服 Shape0 是**缓回药**：`PlayerObject.UseItem` 把回复量累加进 `PotHealthAmount/PotManaAmount`（`MapObject` 上的 public ushort），再由 `HumanObject.Process()` 按 `PotDelay` 慢慢释放。
   - 不挡一下会一秒一瓶。修法照抄服务端英雄自己的判断：`if (needHP && p.PotHealthAmount > 0) needHP = false;`（蓝同理）。

4. **战斗分支顺序让远程职业「技能白给」（已修，重要）**
   - 现象：`CombatUpdate` 里 `dist <= 1` 的肉搏分支排在放技能之前。而怪一定会凑上来 → 法师/道士/弓箭手一旦接战就在 dist1，**永远走不到放技能那条分支**，等于白配技能。
   - 修法：抽出 `TryCastAttack(target, dist)`（`_attackSpell` 是 None/DoubleSlash 直接 false；否则 `range>0 && dist<=range` 就 `p.Magic(...)` 并返回 true），并且**提到 `dist<=1` 分支的最前面**再兜底肉搏。

### 二、补上「假人没技能」这个最大缺口（新增 `LearnBasicSpells`）

- 原状：`FakePlayerManager` 里完全没有 Magic 相关代码 → 法师/道士只能肉搏。
- 关键洞察：**`Spell` 枚举在 `Shared/Enums.cs` 里本来就是按职业分段排的**（战士 1-30 / 法师 31-60 / 道士 61-90 / 刺客 91-120 / 弓箭 121-150 / Custom 151+），所以按数值区间判断归属即可，**不用逐个点名**，服务端技能表怎么改都不会漏。`MagicInfo` 本身没有职业字段，靠这招绕开。
- 实现：`LearnBasicSpells(bot)` 在本职业区间内遍历 `Spell`，`new UserMagic((Spell)s)` 后 `Info == null` 就跳过（等价于「技能表里没这招」）；门槛看 `magic.Info.Level1 <= bot.Level`；等级按 `Level2/Level3` 反推到 0~3，其中 30% 概率故意差一级。
- 调用位置必须在 `new FakePlayerBrain(bot)` **之前**（大脑构造函数里就 `PickSpells()` 读 `GetMagic`）。现已放在 `GivePotions(bot)` 之后、最后的 `RefreshStats()` 之前。
- 配套：大脑 `PickSpells` 里道士 `_attackSpell` 回落到 `SoulFireBall`，**绝不能回落到 `Spell.Healing`**（那会把怪治活）。

### 三、全链路走读验证（都是「会崩/会静止」级别的点，逐个确认过）

- **谁驱动假人的 `Process()`**：不是连接轮询。主循环 `Envir.cs:683-693` 遍历 `Envir.Objects` 链表，`Time > current.Value.OperateTime` 就 `Process() + SetOperateTime()`；而 `MapObject.Spawned()` 里就有 `Node = Envir.Objects.AddLast(this)` → 假人上线即被驱动。`HumanObject.SetOperateTime()` 是 `OperateTime = Envir.Time` → **每帧都跑**（50 假人 ≈ 50 真人的 Process 成本，AI 自己卡 380~700ms）。
- **客户端怎么看见假人**：`PlayerObject` **没有** override `Spawned()`，走的是 `MapObject.Spawned()` → `BroadcastInfo()`；`HumanObject.BroadcastInfo()` 遍历 `CurrentMap.Players` 逐个发 `GetInfoEx`。而 `Map.AddObject(ob)` 里 `if (ob.Race == ObjectType.Player) Players.Add(...)` → 所以 `Spawn()` 里 `map.AddObject(bot)` 必须在 `bot.Spawned()` 之前（现顺序正确）。
- **`MountInfo` 不能是 null**：`CharacterInfo.Mount` 是无初始化的裸字段，而 `CanAttack/CanCast` 会解引用 `Mount.CanAttack`。已在 `PlayerObject.Load()` 里 `info.Mount = new MountInfo(this)` → 假人走同一个 Load，安全。
- **`Account` 必须先赋值**：`Load()` 里 `Account = Connection.Account; if (Account.AdminAccount)` → 空连接下 `Account` 是 null 就 NRE。`Login()` 里用对象初始化器 `new BotConnection(...) { Account = rec.Account }`，在 `new FakePlayerObject(...)` 之前，顺序正确。`AdminAccount` 默认 false → 假人不是 GM，在线计数才会正常加减。
- **重登能复用同一个 CharacterInfo**：`Load()` 开头 `if (info.Player != null) throw`。`PlayerObject.StopGame()` 末尾调 `CleanUp()` → `PlayerObject.CleanUp()` → `base.CleanUp()`（`HumanObject.CleanUp()`）里 `Connection.Player = null; Info.Player = null; Info.Mount = null;`。所以下线后再上线不会抛异常 —— **否则每个假人只能上线一次**，之后连续失败 5 次被永久放弃，在线人数会慢慢掉到 0。
- **空连接不会被「超时踢线」扫到**：`MirConnection.Process()` 开头是 `if (_client == null || !_client.Connected) { Disconnect(20); return; }`，但 `BotConnection` override 成空实现；且假人连接**从不加入** `Envir.Connections`（那里是 `Network_ClientConnected` 才加），所以 `Connections[i].Process()` 与关服的 `StopNetwork()` 都扫不到它们。
- **下线路径安全**：`CleanObservers()` 只遍历 connection 自己的 `Observers`（假人为空）；`Report.Disconnected()` → `Reporting.LogMessage()`，那里已 `if (_player is FakePlayerObject) return;` → 不写玩家日志。
- **`CanEquipItem` 是完备的**（`HumanObject.cs:7898`）：校验 EquipmentSlot↔ItemType 对应、`RequiredGender.HasFlag`、`RequiredClass.HasFlag`、以及全部 `RequiredType`（Level/MaxLevel/MaxAC/MaxDC...）。注意它**没有**校验 `RequiredClass.弓箭`（原服遗留），但假人自己的 `((byte)info.RequiredClass & classFlag)` 已经卡住了。
- **枚举取值核对**：`MirClass` 是 0..4（战士0/法师1/道士2/刺客3/弓箭4）→ `OnlineRankingCount[(int)Class+1]` 落在 1..5，而数组是 `new int[6]`，安全。`RequiredClass` 才是位掩码（战士1/法师2/道士4/刺客8/弓箭16），`ClassFlag(cls) => 1 << (int)cls` 对齐。
- **`InIReader.FindValue` 是按段严格扫描的**（`Shared/Functions/IniReader.cs`：先精确匹配 `[section]` 行，再向后找 key，遇到下一个 `[...]` 就 return null）→ 追加在文件末尾的 `[FakePlayer]` **不会**污染任何老键。已用脚本验证 8 个新键全可读、`[Network] Port=7000` 未受影响。

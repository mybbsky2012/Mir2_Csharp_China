二、Settings.Save() 批量化（Server/Settings.cs）
按客户端 11-04 那套结构拆开：
csharppublic static void Save()
{
    Reader.BeginBatch();
    try { SaveCore(); }
    finally { Reader.EndBatch(); }      // finally 必须留，否则异常后静默不落盘
}

顺带发现一个剩下的大头：SaveCore() 最后一句 SaveAwakeAttribute() 自己新建了一个 InIReader，写约 50 个键，每个键都把整份 AwakeningSystem.ini 重写一遍，这 40~50ms 就是批量化后剩下来的主要开销。所以它也改成 BeginBatch / WriteAwakeAttribute(reader) / finally EndBatch。
实测（新加了 UiShot.exe savetime 模式，在临时目录里跑真实的 Settings.Save()，不碰现网配置）：
添加到对话版本单次 Save改前340 / 345 / 360 ms只改 Settings.Save61 / 57 / 70 ms连 Awake 也批量化9.0 / 7.3 / 8.5 / 6.9 / 6.0 ms
数据完整性也核对了：Setup.ini 键数 212 → 212 不变；AwakeningSystem.ini 生成 62 键，与现网文件的键集合完全一致（缺失 0、多出 0）；initest（保存→重载往返）PASS。

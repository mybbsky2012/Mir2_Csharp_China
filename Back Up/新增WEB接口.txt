新增 4 个接口（都使用同一把 HTTPQueryKey）
1. /accounts — 账号分页列表

plaintext

http://127.0.0.1:5679/accounts?key=密钥&page=1&size=20
可选：&filter=神秘   &online=1   &banned=1
参数：page（默认1）、size（默认20，上限200）、filter（模糊匹配账号、用户名、邮箱、角色名、最后IP）、online=1|0、banned=1|0
排序：按账号序号倒序，新号在前；这样分页稳定，不会漏掉或重复账号
每个账号返回：account / userName / email / admin / online / banned / banReason / banExpire / creationDate / lastDate / lastIP / characters[]；在线时多一个 playing{name,level,map,x,y}，直接看到“在玩哪个号、在哪张图”
顶层还带 total / pages / onlineCount / bannedCount，以及内嵌的 server 状态块，一屏就能看到全貌
2. /serverstatus — 服务器运行状态与倍率

json

{"gameName":"...","running":true,"startedAt":"2026-10-30 09:12:03",
 "uptimeSeconds":16923,"uptimeText":"4小时42分",
 "onlinePlayers":12,"connections":15,
 "expRate":2,"highLevelExpRate":1.5,"highLevelExpRateMinLevel":60,
 "dropRate":1.5,"saveDelayMinutes":5}
expRate 为全局经验倍率，highLevelExpRate/MinLevel 为高等级额外加成，dropRate 为爆率倍率（倍率越高，越容易掉落）。

3. /ban 与 /unban — 封禁与解封

plaintext

/ban?key=密钥&id=账号&reason=使用外挂&days=7        （按小时：&hours=12）
/ban?key=密钥&name=角色名&reason=恶意刷屏          （days/hours 都不填 = 永久）
/unban?key=密钥&id=账号
返回 {"ok":true,"account":"xxx","banned":true,"reason":"...","expire":"2026-11-06 13:43:00","kicked":true}；找不到账号返回 notfound。

4. /kick — 只踢下线不封号，返回 offline 表示当前不在线。

写操作的安全性设计（重点）
不跨线程碰 socket 或存档文件：HTTP 线程只改内存字段并入队，真正的 SendDisconnect 和“立即存档”由游戏工作线程在下一拍执行（Envir 新增 HttpSaveRequested 和踢人队列，先踢人再存档，保证下线状态也写入文件）；
锁与登录同源：账号读写统一使用 Envir.AccountLock（和登录、断开、建号同一把锁），不是随手 lock 账号列表；
没有死锁隐患：服务器状态块在账号锁之外获取（它在锁内容易形成 AccountLock→Connections，和游戏线程 Connections→AccountLock 反向）；踢人队列锁也保证先释放、再调用断链；
审计留痕：封禁/解封/踢人都会往服务端日志打一条 [管理接口] 账号 xxx 已封禁，原因：…，已踢下线。
排雷说明
只改了 HttpServer.cs（新增路由和方法）与 Envir.cs（新增队列与处理函数，并在主循环 Process() 之后加一次消费），游戏主流程、战斗、掉落全未触碰；
永久封禁用“当前时间 + 30 年”而非 DateTime.MaxValue，避免客户端倒计时溢出；
解封会同时清空原因与到期时间，与原版登录逻辑（到期自动解封）一致。

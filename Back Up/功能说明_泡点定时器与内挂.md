# 新增功能说明：泡点循环定时器 / 客户端内挂 / 服务器开关（免蜡·穿人·免助跑·超负重·泰山）

本次改动基于 Crystal 血统工程（.NET 8 / C#）。分为三组：

1. **泡点升级**：NPC 循环定时器；
2. **客户端内挂**：自动挂机 + 开关面板；
3. **服务器端开关**：免蜡 / 穿人（含穿怪、穿 NPC）/ 免助跑 / 超负重 / 泰山。

> 后续追加记录：
> - 新增 **免助跑** 开关，并把开关偏好改为客户端自动恢复（见 2.3）。
> - 新增 **超负重** 与 **泰山** 两个开关（见 3.5 / 3.6）。
> - **穿人** 扩展到可穿 NPC（原仅穿玩家 / 英雄 / 怪物，见 3.3）。

## 一、泡点升级：NPC 循环定时器

原有 `SETTIMER` / `CHECKTIMER` / `EXPIRETIMER` 的语义是「一次性倒计时 + 客户端弹计时条」，
**不循环、也不执行脚本**。新增的循环定时器与之并存、互不干扰。

### 1.1 脚本命令

| 命令 | 位置 | 语法 | 说明 |
|---|---|---|---|
| `SETLOOPTIMER` | `#ACT` | `SETLOOPTIMER 名称 间隔秒数 标签` | 开启循环定时器，每 N 秒执行一次指定标签页 |
| `CHECKLOOPTIMER` | `#IF` | `CHECKLOOPTIMER 名称` | 判断该定时器是否正在运行 |
| `EXPIRETIMER` | `#ACT` | `EXPIRETIMER 名称` | 关闭定时器（同时关掉同名的普通计时器与循环定时器） |

参数说明：

- **名称**：定时器唯一标识，同名会覆盖（相当于重置计时）。
- **间隔秒数**：正整数，最小 1 秒；非数字会写入服务端日志并忽略。
- **标签**：要执行的脚本页。写 `泡点奖励`、`@泡点奖励`、`[@泡点奖励]` 均可，内部会统一成 `[@泡点奖励]`。

### 1.2 行为要点

- 定时器**保存在玩家对象上**，下线 / 小退 / 角色死亡回城时会自动清空（`StopGame()` 里 `ClearLoopTimers()`）。
- 每次触发**静默执行**脚本页：只跑 `#ACT`，不会弹出 NPC 对话框、不会打断玩家当前操作。
- 执行时会保存并还原 NPC 上下文（`NPCObjectID`/`NPCScriptID`/`NPCPage`/`NPCDelayed` 等），
  因此在泡点脚本里继续调用其他 NPC 命令是安全的。
- 脚本页中可以用 `EXPIRETIMER 名称`（或 `CLOSE`）自行结束泡点，也可用条件判断做「时间到就停」。
- GM 用 `@ReloadNPC` 之类重载脚本后，找不到原脚本的定时器会被自动丢弃，不会抛异常。

### 1.3 示例脚本

见 `Envir/NPCs/泡点示例.txt`，核心结构：

```
[@MAIN]
#SAY
欢迎来到泡点地图。\
<开始泡点/@开始> <停止泡点/@停止> <查看状态/@状态>

[@开始]
#IF
CHECKLOOPTIMER 泡点
#ACT
MESSAGEBOX "泡点已在进行中。"
BREAK

#ACT
SETLOOPTIMER 泡点 60 泡点奖励
SENDMSG 6 "泡点已开启，每 60 秒获得一次经验。"

[@泡点奖励]
#ACT
GIVEEXP %USERNAME 100000
SENDMSG 6 "获得泡点经验 100000。"

[@停止]
#ACT
EXPIRETIMER 泡点
SENDMSG 6 "泡点已停止。"
```

> 提示：把 `SETLOOPTIMER` 放在 `[@开始]` 里，`[@泡点奖励]` 就是「被定时调用的页」。
> 若想让泡点奖励随在线时长递增，可在 `[@泡点奖励]` 内用变量累加经验值。

### 1.4 常见问题：泡点「开着但没反应」

**症状**：NPC 能打开、点「开始泡点」也有提示，但到时间不加经验、聊天框毫无动静。

**根因**：Crystal 的 NPC 页面是**按按钮链逐步发现**的。
`NPCScript.ParsePages()` 只解析两批页面：

1. `[@MAIN]`（固定入口）；
2. 从已解析页面里、通过 `<文字/@标签>` 按钮能跳到的页面（递归展开）。

而泡点的触发页（如 `[@泡点奖励]`）是被 `SETLOOPTIMER` **动态引用**的，
按常规写法**没有任何按钮指向它**，于是它不会被收进 `NPCPages`。
`CallSilent()` 遍历 `NPCPages` 找不到该页 → 直接返回 false → 静默什么都不做。
表现就是「泡点开了，但永远不触发」。

**修复**（`Server/MirObjects/NPC/NPCScript.cs`）：

- 新增 `_rawLines` 字段：保存 `#INCLUDE` / `#INSERT` 展开之后的脚本原始行；
- 新增 `_dynamicPages` 缓存字典：避免定时器每次触发都重新解析整个脚本；
- `CallSilent()` 在 `NPCPages` 里找不到目标页时，用 `_rawLines` 现场 `ParsePage()` 解析并缓存；
  只有该段落确实不存在（解析出的 `SegmentList` 为空）时才返回 false。

**结论**：触发页**不需要**任何按钮指向它，写在同一个脚本文件里即可。
`[@MAIN]` → `[@开始]`（按钮）→ `[@泡点奖励]`（定时器动态调用）这种写法现在可以正常工作。

## 二、客户端内挂（自动挂机）

### 2.1 打开方式

按 **Home** 键开关内挂面板，按 **End** 键开关内挂总开关（快捷键可在 `KeyBindSettings` 中改）。

面板提供以下勾选项：

| 选项 | 作用 |
|---|---|
| 内挂总开关 | 总闸，关闭后所有自动行为停止 |
| 自动攻击 | 自动在搜索半径内选最近的怪物并攻击 |
| 自动走位 | 目标超出攻击距离 / 需要捡物时自动走（可跑）过去 |
| 走位跑步 | 自动走位时优先跑动（路况不佳自动降级为走路） |
| 自动技能 | 按需自动用技能：远怪用远程、近怪开近攻、围攻用群攻（见 2.5） |
| 自动躲避 | 被怪物围攻（周身 1 格内 ≥ 3 只）时自动走开（见 2.6） |
| 毒符互换 | 道士专属：护身符位按「要放的技能」在「符」与「毒粉」间切换；两种毒粉（黄色/灰色）**一次使用交替一次**，不会来回乱切。**勾选即生效，不需要开内挂总开关**（见 2.13） |
| 自动捡物 | 脚下的物品直接拾取，远处的走/跑过去拾取 |
| 自动喝血药 | HP 低于设定百分比时自动喝药 |
| 自动喝蓝药 | MP 低于设定百分比时自动喝药 |
| 免蜡 | 见第三节（需服务器开放） |
| 穿人/怪/NPC | 见第三节（需服务器开放） |
| 免助跑 | 见第三节（服务器始终放行） |
| 超负重 | 见第三节（需服务器开放） |
| 泰山(不后仰) | 见第三节（需服务器开放） |

面板为两列布局（行距 24，每列 8 行）：左列 = 纯本地开关（总开关、自动攻击/走位/捡物/喝药/技能、毒符互换），
右列 = 走位跑步、自动躲避（本地）与服务器放行开关（免蜡 / 穿人 / 免助跑 / 超负重 / 泰山）。

### 2.3 开关偏好会自动恢复

`NoLamp / WalkThrough / NoRunUp / OverWeight / MountTai` 这五个是**服务器开关**：
服务器在每个角色登录时会把它们统一置为「关闭」并下发（服务器侧不持久化这些状态），
所以客户端不能直接用下发值覆盖本地设置，否则每次上线都得手动重开。

客户端为此把「玩家偏好」单独存一份（`Settings.Preferred*`），并只把偏好写进 ini；
进图 1.5 秒后由 `GameScene.RestorePlayerOptions()` 按偏好把**服务器已开放且玩家原本勾选**的开关
重新申请一次（是否生效仍由服务器回执决定，未开放的功能不会被反复申请，也不会刷屏提示）。

切勾选时 `RequestPlayerOption()` 会同步更新偏好，所以取消勾选同样会被记住。

### 2.4 设计取舍

内挂**只做决策**（索敌 / 捡物 / 喝药 / 选技能 / 走位），攻击与施法动作复用 `CheckInput()` 中既有的
`TargetObject` 自动攻击、`NextMagic` 施法流程，避免重复实现战斗判定导致的手感差异。

喝药只使用 `ItemType.药水` 且 `Shape` 为 0（普通药水）或 1（太阳水）的道具，不会误喝其它类型。

内挂会在以下情况暂停：角色死亡、观战、麻痹 / 冰冻 / 眩晕状态、正在播放觉醒动作。

### 2.5 自动技能（按需选技能）

`Settings.AutoSkill`（面板勾选「自动技能」）开启后，`GameScene.AutoPlayAutoSkill()`
在选中目标后按「围攻 → 远程 → 近战」三级决策：

1. **被围攻**（周身 1 格内 ≥ 3 只怪）：优先放**群攻技能**；放不出群攻（没学/冷却/没蓝）且勾了
   「自动躲避」时自动走开躲避。
2. **远怪**：按优先级放**远程单体技能**（法师：雷电术→灭天火→冰咆哮→强化大火球→大火球→火球；
   道士：灵魂火符；弓手：双箭→元素之箭→...）。战士/刺客没有远程技能，自然落到普通攻击。
3. **近怪**：战士/刺客自动把**近攻开关技**打开（刺杀剑术、半月弯刀、狂风斩、烈火剑法；
   刺客：风剑术），本次登录只尝试开启一次并保持常开，攻击本身仍走普通攻击流程。

技能只会从**已学会**的技能里挑（`UserObject.GetMagic()`），并校验冷却（`CastTime + Delay`）
与 MP 消耗；施法复用 `NextMagic → UseMagic()` 流程，射程、目标合法性由原有代码统一校验。
玩家手动按的技能优先（`NextMagic` 已挂起时自动技能不抢）。

**施法材料校验**（`AutoPlayHasSpellMaterials()`）：道士的符系技能服务端都要消耗护身符
（灵魂火符 / 隐身术 / 群体隐身 / 幽灵盾 / 神圣战甲术 各 1 张；阴阳五行阵-秘籍 3 张；
毒雾要 5 张符 + 5 个绿毒）。
材料不够时服务端会**静默失败但照样扣蓝**，因此内挂选技能时直接跳过这类技能，
避免出现「锁定目标原地反复施法打不中」的情况。护身符/毒药看的是**装备槽**
（`EquipmentSlot.护身符`，与服务端 `GetAmulet` / `GetPoison` 一致），不是背包。

**射程校验与自动接近**：`AutoPlayTryCast` 会校验技能射程（`magic.Range`），
够不到的技能直接跳过不施放；若技能都已就绪但目标超出射程，
内挂会自动跑/走**移动到打得到的位置**（`AutoPlayHasReadySpell` 判定），
到位后下一帧自动施法，避免「锁定目标原地反复施法却不接近」的死循环。

### 2.6 走位跑步与自动躲避

**走位跑步**（`Settings.AutoMoveRun`，默认开）：
`AutoPlayStepTo()` 与 `CheckInput()` 的追击段都改为优先跑动——与手动跑步相同的路况校验
（`CanRun`、门是否打开、`NextRunTime`、HP ≥ 10、潜行规则），跑不动自动降级为走一步。
追击跑动的距离门槛按职业区分：**战士仍 ≥ 3 格才跑**（近身逐步走，避免冲过头），
**其他职业（法师/道士/刺客/弓手）目标 ≥ 2 格就跑**——跑 2 格正好贴脸停下，
刺客随后照常施展近攻技能；骑马/疾跑时跑 3 格。

**弓手/法师走位**（`AutoPlayCombatMove()`）：弓手追击在 `CheckInput` 里被「ArcherTest - stop walking」
拦掉，因此由内挂接管——目标超出 `Globals.MaxAttackRange`（9 格）时跑/走追过去；
目标贴脸（距离 ≤ 2）时向离目标更远的方向**拉开**（放风筝），拉开的那一帧清空目标，
避免攻击动作覆盖移动动作，下一帧恢复正常攻击。
**法师与弓手同款**：内挂开启时法师也走这套走位（超距追、贴脸拉开），
并在 `CheckInput` 里被禁止近距攻击（`近距攻击1`）与自动追向目标，
只靠法术远程输出；法师没有远程普通攻击，因此即使没勾「自动技能」也会自动放法术
（等同弓手的远程攻击）。

**自动躲避**（`Settings.AutoDodge`，默认关）：被围攻且放不出群攻时，
`AutoPlayDodgeStep()` 在八方向里挑「周围怪物更少、且尽量不离目标超过 2 格」的格子走开；
四周全堵死时不动（回头继续打）。
躲避同样支持跑动：开了「走位跑步」时每个方向同时评估「走一步」和「跑 2/3 格」两个落点，
按安全性择优（跑动中间格子全通才会跑，跑不通自动降级为走），
拉开（放风筝）优先跑得更远，躲避优先选怪物更少的落点。

### 2.7 自动寻怪与跑图

开启「自动攻击」后，附近（`AutoSearchRange` 内）没怪时内挂会自己找怪：

1. **扩大搜索**：把搜索半径扩大一倍，视野内还有怪就跑/走追过去，
   进入攻击半径后自然转入正常战斗流程（期间不锁定目标，避免隔墙误攻击）。
2. **卡住绕路**：直线追怪被地形挡住（2.5 秒位置没变化）时，暂时转随机游走绕路，
   4 秒后再重新尝试直追，避免顶着墙原地卡死。
3. **定向游走**：彻底没怪时沿当前方向持续游走（每 600ms 一步，复用 `AutoPlayStepTo`，
   同样支持跑动、避开未开的门），每 3 秒随机换一次方向，实现自动跑图找怪。
4. **捡物优先**：跑图前先检查地上的物品（`AutoPlayPickUpItem` 改为返回是否处理了物品），
   有东西可捡优先捡，捡完继续找怪。

### 2.8 自动治疗技能（血量不足自动补一口）

血量低于「自动喝药 HP 阈值」（`AutoPotHPPercent`）时，除了喝药（照常进行），
内挂还会自动使用**治愈术系技能**回血（`AutoPlayHealSpells`，只从已学会的技能里挑）：

- 治愈术 / 治愈术-秘籍（`Healing` / `HealingRare`）
- 治愈圆环 / 秘籍（`HealingCircle` / `HealingcircleRare`，脚下持续回血）
- 群体治愈术（`MassHealing`）

施法以自己为目标复用 `NextMagic → UseMagic()` 流程，冷却与 MP 消耗照常校验；
玩家手动按的技能优先。注意：本引擎没有主动回蓝技能（气功术为被动），
MP 不足仍然只靠喝药。

### 2.9 道士专属：灵魂火符主攻 + 隐身流 + 辅助技能 + 自己/宠物/队友加血

内挂开启且职业是**道士**时，`ProcessAutoPlay()` 会额外跑两个辅助流程
（都只从**已学会**的技能里挑，并按原有施法流程校验冷却 / MP，玩家手动施法时不抢）：

**① 战斗节奏：灵魂火符为主攻，隐身贴脸才近砍**（`AutoPlayAutoSkill()`）
道士不开弓手/法师那套放风筝走位（不往后退），追击仍由 `CheckInput` 负责。
远程技能表里道士只有**灵魂火符**（射程 9），因此它天然就是道士的**主攻技能**；
配合 2.13 的毒符互换，先补一发**施毒术**（目标还缺某种毒时），随后一直丢灵魂火符。

唯一的近砍情形（`AutoPlayMonsterMeleeAdjacent()`）：**隐身中** 且 目标贴着 1 格 且
该怪**正在近身攻击自己**（用 `S.Struck` 的 `AttackerID` 判定「真的打到我身上」，
退而用怪物攻击动作里的 `TargetID`）→ 这一小段（`AutoTaoistMeleeWindow`，1 秒）
不挂技能，交给 `CheckInput` 的「近距攻击1」正常砍，砍完立刻恢复远程施法。
其余情况（没隐身 / 怪没贴脸 / 怪只是站着）一律不放近攻，纯远攻。

**② 辅助技能：隐身术 / 幽灵盾 / 神圣战甲术**（`AutoPlayTaoistSupport()`，节流 800ms）
检查自身 buff 列表（`BuffsDialog`），缺哪个补哪个：

| 技能 | buff | 作用 | 内挂的额外条件 |
| --- | --- | --- | --- |
| 隐身术 `Hiding` | `BuffType.隐身术` | 自己隐身 | **有召唤宠物** 且 **附近 ≥2 只怪** 才放 |
| 幽灵盾 `SoulShield` | `BuffType.幽灵盾` | 提高**魔法防御**（MaxMAC） | — |
| 神圣战甲术 `BlessedArmour` | `BuffType.神圣战甲术` | 提高**物理防御**（MaxAC） | — |

三者服务端都要**消耗护身符**，没有护身符时会静默失败却照样扣蓝，
因此内挂先在客户端检查装备槽（`AutoPlayHasAmulet()` / `AutoPlayHasItem()`），没材料就不放。

**隐身流的配套规则**（`AutoPlayUpdateHiding()` / `AutoPlayShouldHide()` / `AutoPlayHoldStill()`）：

- **隐身条件是「有宝宝 + 怪多」**：`AutoPlayShouldHide()` 要求身上有自己的召唤物
  （`AutoPlayHasOwnPet()`，名字以 `(自己角色名)` 结尾）且附近（半径
  `AutoPlayHideRange()` = min(索敌半径, 8)，不超过灵魂火符射程 9）有 **2 只以上**怪物。
  怪太少没必要隐身，没宝宝则没人顶怪——都不是隐身的场景。没勾「自动技能」也不隐身
  （不放技能时隐身只会站着挨打）。
- **中毒时不隐身**：自己身上有绿毒 / 红毒（`AutoPlaySelfPoisoned()`）时**不进入隐身**；
  已经在隐身中又中了毒、且持续 `AutoPlayHidePoisonBreakTime`（**25 秒**）→ **自动解除隐身**，
  改为主动攻击目标。
- **隐身 25 秒没打到怪 → 自动解除隐身**：`AutoPlayUpdateHiding()` 每帧记录「本次隐身开始时间」
  和「隐身后最近一次对怪物出手的时间」（`AutoPlayTryCast()` 里记），
  连续 `AutoPlayHideIdleBreakTime`（**25 秒**）没打到怪（够不到 / 没符纸材料等）→ 解除隐身去主动打。
  对自己上的辅助技能（幽灵盾等）不算「攻击怪物」。
- **隐身期间原地不动**：服务端 `HumanObject.Walk()` / `Run()` 里，走 / 跑都会立刻
  `RemoveBuff(BuffType.隐身术)`，所以内挂隐身时把**所有移动入口**都关掉
  （走位 `AutoPlayCombatMove` / 躲避 `AutoPlayDodge` / 追射程 `AutoPlayStepTo` /
  跑图 `AutoPlayRoam` / 打不中换位），只站在原地丢灵魂火符、施毒术。
- **解除隐身的实现方式**：不是直接删 buff，而是把「原地不动」放开——移动一步服务端就会
  解除隐身；同时 `AutoPlayHideBanTime`（8 秒）内不再隐身，先把该打的怪打掉。
  另外射程内**一只可打的怪都没有**时也会放行移动（`AutoPlayHoldStill()` 返回 false），
  避免彻底卡死。

**③ 给自己 / 宠物 / 队友加血**（`AutoPlayGroupHeal()`，节流 1s）
把三类单位汇总到一起判断——**自己**（`User`）、**自己召唤的宠物**（名字以 `(自己角色名)` 结尾的怪物）、
**队伍队友**（`GroupDialog.GroupList`）——凡血量低于 `AutoPlayAllyHealPercent`（80%）
且在 9 格射程内的都算「掉血单位」：

- 一片区域（3×3 范围）内有 **2 个及以上**单位掉血（全体失血）→ 用**群体治疗术**（`MassHealing`），
  以「周围掉血单位最多」的那个位置为中心施放（服务端按落点 3×3 结算，宠物、队友一起奶）；
- 只有 **1 个单位**掉血 → 用**单体治愈术**（`Healing` / `HealingRare`）；自己掉血优先治自己
  （自己的候选表更全，含治愈圆环 `HealingCircle`）。

道士的自身治疗统一在这里处理（非道士职业仍走 2.8 的 `AutoPlayAutoHeal()`），
所以道士不会再出现「自己先抢着放单体治愈、把群体治疗术的机会挤掉」的情况。
英雄（Hero）不在队伍名单里，但站在群体治疗术范围内时同样会被治疗到。

### 2.10 法师 / 道士：打不动的怪物自动降级（魔法 → 物理 → 换怪）

服务端**只有在真正打出伤害时**才广播受击包（`S.ObjectStruck`；被完全挡下 / 免疫时
只广播 Miss），客户端因此能判断「自己的攻击有没有生效」——`MapObject.LastStruckByMeTime`
记录「最近一次被自己（或自己的英雄）打出伤害的时间」，内挂据此做**三级降级**
（`AutoPlayUpdateMagicImmunity()`，法师 / 道士专用）：

| 阶段 | 行为 | 升级到下一阶段的条件 |
| --- | --- | --- |
| ① 魔法阶段 | 照常放法术（灵魂火符 / 雷电术…） | 持续施法 `AutoPlayMagicProbeTime`（4 秒）仍无受击 → 判魔法无效 |
| ② 物理阶段 | **停止施法**，走到贴身 1 格用「近距攻击1」砍 | 靠近超时 `AutoPlayMeleeReachTime`（5 秒）没贴到 → 视为够不到；贴身砍 `AutoPlayPhysicalProbeTime`（4 秒）仍无受击 → 判物理也无效 |
| ③ 放弃目标 | 拉黑该目标 ID 与**同名怪** `AutoPlayImmuneBlackTime`（30 秒），随机换位重新索敌 | — |

要点：

- 魔法阶段计时从**第一次真正挂起施法**开始，且要求「最近 `AutoPlayCastAliveTime`（4 秒）
  内仍在施法」—— 跑位中 / 没蓝 / 护身符不够时不会被误判成魔法无效。
- 物理阶段只在**贴身之后**才开始计时，走路的时间不算。
- 只要自己打出了伤害，当前阶段计时立即重置（已切到物理的保持物理模式，不再回头试魔法）。
- 按名字拉黑只在「**确实贴身砍过**还是打不动」时生效，避免因为被墙挡住（位置问题）
  误把一整类怪拉黑。同名怪 30 秒内不再被选为目标，直接去找下一只。
- 切换时在聊天窗给提示：「魔法对××无效，改用物理攻击」/「物理攻击对××也无效，放弃该目标」。
- 配套的 `CheckInput` 改动：法师挂机时仍默认不近攻、追击也不主动贴身，
  **只有**该目标进入物理阶段（`AutoPlayIsPhysicalTarget()` 为真）才解禁
  「近距攻击1」与贴身追击；法师的自动走位在物理阶段也从「放风筝拉开」改为「主动贴身」。
- 其他职业仍用原有的通用「打不中检测」（持续攻击 6 秒无受击 → 拉黑 8 秒换位）。

### 2.11 法师专属：自动开魔法盾 + 按需群攻（火墙 / 地狱雷光 / 抗拒火环 / 疾光电影 / 圣言术）

**① 自动开魔法盾**（`AutoPlayMageSupport()`，节流 800ms）
检查自身 buff 列表，没有 `BuffType.魔法盾` 就补一个（施法目标是自己，复用 `NextMagic → UseMagic()` 流程）。
服务端的魔法盾是限时 buff，到期自动续。

**② 按需群攻**（`AutoPlayMageCombat()`，插在通用流程前，都没命中才落到普通远程单体技能）

| 场景 | 判定 | 技能 |
| --- | --- | --- |
| 被怪围攻 | 周身 **1 格**内 ≥ `AutoPlaySurroundCount`（3）只怪 | ①**地狱雷光**（`ThunderStorm`，周身范围伤害）→ ②**抗拒火环**（`Repulsion`，把贴脸的怪推开）→ ③原有群攻表 → ④躲避 |
| 遇群怪 | 某个怪周围 **3×3** 内有 ≥ `AutoPlayClusterMinCount`（3）只怪 | **火墙**（`FireWall`）落在「怪最密集」的那只怪脚下（火墙落点是十字 5 格，服务端会自己铺开） |
| 怪排成一条线 | 沿 8 个方向各数 6 格，某方向 ≥ `AutoPlayLineMinCount`（3）只怪 | **疾光电影**（`Lightning`）朝该方向打，服务端沿此方向穿透 6 格（与服务端 `case Spell.Lightning` 的循环格数一致） |
| 不死系怪 | 怪物名命中 `AutoSaintKeywords` 关键字 | **圣言术**（`TurnUndead`，服务端只对 `Undead` 怪物生效） |

实现要点：

- **被围攻时不再后撤**：`AutoPlayCombatMove()` 里加了一条——法师被围攻（1 格内 ≥ 3 只）时不做「放风筝拉开」，
  否则每帧都在往后跑、技能永远轮不到放，改由地狱雷光 / 抗拒火环处理。
- **火墙节流** `AutoPlayFireWallInterval`（5 秒）：火墙落点能烧十几秒，同一处反复放是白耗蓝
  （服务端对同一格已有的火墙不会再建，但法力已经扣了）。
- **圣言术节流** `AutoPlaySaintInterval`（5 秒）：这招很费蓝（基础 52 + 每级 13），
  对高级不死系还容易失败，失败照样扣蓝，所以限制重试频率，中间用普通技能补输出。
- **不死系识别**：客户端拿不到服务端的怪物 `Undead` 标记（`S.ObjectMonster` 包里没有这个字段），
  这里按**怪物名字关键字**判断，关键字可在 `Mir2.ini` 的 `[AutoPlay]` 段调整：
  ```ini
  AutoSaintKeywords=僵尸,骷髅,白骨,腐尸,尸,亡灵,死灵,幽灵,幽魂,巫妖,骨
  ```
  名字里含任一关键字就当不死系。清空该项会自动恢复默认值。

### 2.12 道士专属：自动召唤（骷髅 + 神兽 + 月灵 三只同时养）

`AutoPlayTaoistSummon()`（重试间隔 `AutoPlaySummonInterval` = 3 秒）：
按 **骷髅 → 神兽 → 月灵** 的顺序逐个检查，**哪一只数量为 0 就补哪一只**，
三只都在场就不再召唤（`AutoPlayPetCount()`）：

| 顺序 | 技能 | 召唤物（服务端配置名） | 消耗护身符 |
| --- | --- | --- | --- |
| 1 | 召唤骷髅 `SummonSkeleton` | 变异骷髅（`SkeletonName`） | 1 张 |
| 2 | 召唤神兽 `SummonShinsu` | 神兽（`ShinsuName`） | 5 张 |
| 3 | 精魂召唤术 `SummonHolyDeva` | 月灵（`AngelName`） | 2 张 |

要点：

- **判断「某只已经有了」**：服务端把宠物名写成「怪物名(主人名)」（`MonsterObject.Name` 的 getter），
  所以客户端按「名字以 `(自己的角色名)` 结尾」+「名字里含关键字（骷髅 / 神兽、圣兽 / 月灵）」
  分别统计每种召唤物的数量（`AutoPlaySummonPetKeywords`）。宠物死亡时服务端会去掉括号后缀，
  于是内挂会自动重新召唤那一只。
- **服务端宠物上限已从 2 调到 3**：`Server/MirObjects/HumanObject.cs` 的
  `SummonSkeleton` / `SummonShinsu` / `SummonHolyDeva` 里
  `Pets.Count(x => x.Race == ObjectType.Monster) >= 3`（原为 `>= 2`）。
  不改这里的话第三只永远召不出来。**改动了服务端，需要重新编译并重启服务端生效。**
- **避免白耗蓝**：服务端在「已有同类宠物 / 宠物已满 / 没有护身符」时会直接返回，
  但**法力是在进入技能处理前就扣掉的**，所以客户端先按种类数量 + 护身符校验
  （`AutoPlayHasSpellMaterials()` 已补上三个召唤术的护符需求），满足才发包。
- 面板上不需要新增开关——跟随内挂总开关运行；召唤术要**已学会**才会被挑中。

### 2.13 道士专属：毒符互换（护身符 ↔ 毒粉，黄/灰毒粉一次使用交替一次）

道士的**护身符**和**毒粉（毒药）**在服务端是同一种物品类型（`ItemType.护身符`），都放在同一个
「护身符」装备槽（`EquipmentSlot.护身符`）里（数据库里的实际物品名/形态）：

| 形态 `Shape` | 物品 | 服务端毒类型 | 用于 |
| --- | --- | --- | --- |
| 0 | 护身符（符） | — | 灵魂火符 / 隐身术 / 集体隐身术 / 幽灵盾 / 神圣战甲术 / 各种召唤 / 阴阳五行阵 |
| 1 | **灰色毒粉**（小/中/大/特） | `PoisonType.Green`（持续掉血） | 施毒术 |
| 2 | **黄色毒粉**（小/中/大/特） | `PoisonType.Red`（削弱防御） | 施毒术 |

> 服务端 `HumanObject` 的施毒术结算里 `item.Info.Shape == 1 → PoisonType.Green`、
> `== 2 → PoisonType.Red`，所以内挂判「目标缺哪种毒」时 Shape 1 对应绿毒、Shape 2 对应红毒。

所以一个槽位放不下「符 + 毒」，内挂**按「接下来要放哪个技能」切换**，而且判定是**粘性**的
（面板勾选项「**毒符互换**」= `Settings.AutoSwapPoison`，默认开）。
它有两个触发入口，**互不依赖**：

#### ① 手动操作技能时按需换装（勾选即生效，**不需要开内挂总开关**）

`AutoPlayPrepareManualSpell()`：玩家按技能键 / 点技能栏时（`GameScene.UseSpell` 的 `default` 分支）
先看**这个技能吃什么材料**，然后：

| 技能 | 需要的材料 | 处理 |
| --- | --- | --- |
| 施毒术 `Poisoning` | 黄色毒粉或灰色毒粉（都行） | 换成毒粉；目标还缺哪种就换哪种，目标不缺毒/没有目标就黄/灰交替 |
| 灵魂火符 `SoulFireBall` | 护身符 1 | 换成符 |
| 隐身术 / 集体隐身术 | 护身符 1 | 换成符 |
| 幽灵盾 / 神圣战甲术 | 护身符 1 | 换成符 |
| 困魔咒 / 诅咒术 / 强化术 / 幻影术 | 护身符 1 | 换成符 |
| 阴阳五行阵-秘籍 `HealingcircleRare` | 护身符 3 | 换成符 |
| 召唤骷髅 / 召唤神兽 / 精魂召唤术 | 符 1 / 5 / 2 | 换成符 |
| 回生术 `Reincarnation` | 护身符 3 | 换成符 |
| 毒雾 / 瘟疫术 | 符 **和** 毒同时消耗 | 不动（一个槽满足不了，交给玩家自己安排） |

- 槽里**已经是要用的材料** → 什么都不做，技能立刻放出去；
- 需要换装 → 先把换装请求发出去，**记住这次技能操作**，等本地装备槽里真的看到目标材料，
  由 `AutoPlayRetryManualSpell()` 自动把这次技能补放出去（一般 100ms 左右，手动体验几乎无延迟）；
- **一次技能操作只换一次、只交替一次**（见下面的「防疯狂互切」）；
- 背包里连对应材料都没有 → 不拦，照常尝试施放（服务端原本就会判失败）；
- 玩家刚手动换过装后 3 秒内是**静默期**（`_autoManualHoldUntil`），自动逻辑不会把槽翻回去。

**毒粉交替规则 —— 一次使用交替一次，不会疯狂乱切**

`_autoPoisonNextShape` 记「**下一次**施毒术要装哪种毒粉」，**第一次先用黄色毒粉**，之后
黄 → 灰 → 黄 → 灰 … 只有**这一次施毒术真的要用出去了**（槽里材料已经就位、或者补放的那一刻）
才把指针换成另一种（`AutoPlayUsePoisonShape()`），所以：

| 第几次用施毒术 | 装进符位的毒粉 |
| --- | --- |
| 第 1 次 | 黄色毒粉（Shape 2） |
| 第 2 次 | 灰色毒粉（Shape 1） |
| 第 3 次 | 黄色毒粉 |
| … | 依次交替 |

目标「只缺某一种毒」时，优先装目标缺的那种（不然放出去也没用），交替指针同样只前进一次。

**防「疯狂互切」的两道闸**（这是「一用需要毒的技能就不停换黄毒/灰毒」的根因修复）：

1. **换装等待期内不再重新判定材料**：只要上一次的换装请求还在路上（`_manualSpellKey != 0` 且未超时），
   同一个技能 / 同样是施毒术再按多少次都直接「继续等」，不会重算一遍该装哪种毒。
   （旧版是在重算之后才判断「是不是同一件材料」，而重算会因为指针已经翻转而算出**另一种颜色**，
   于是每 ~120ms 翻一次：黄 → 灰 → 黄 → 灰 …… 无限循环，看起来就是疯狂换毒。）
2. **补放重入不判材料**：`AutoPlayRetryManualSpell()` 回调 `UseSpell()` 补放时，
   `AutoPlayPrepareManualSpell()` 一进门看到 `_manualSpellCasting` 就直接放行，
   不会再对同一次施法重新做一遍材料判定。

#### ② 自动挂机时按目标需要换装

`AutoPlaySwapPoisonAmulet()`（在内挂主循环里，需要开内挂总开关）：

1. **先判「要不要用毒」（优先级高）**（`AutoPlayWantPoison()`）：
   条件是「学了施毒术 + 有可下毒的目标 + 目标还缺某种毒」。只要成立，接下来就应当放**施毒术**，
   **绝不允许**在这一支里换回符——这是「一用技能就来回互切」的根因，已修掉；
2. **要放吃毒药的技能（施毒术）→ 换毒粉**：槽里不是目标还缺的那种毒时，才把背包里的毒粉装进护身符位，
   原来的符被换回背包（服务端 `EquipItem` 是交换式移动，不会丢东西）；
   槽里**正好是**目标还缺的那种毒时**什么都不做**（保持住，等施毒术把它放出去）；
3. **只有「不需要毒」时才判「要不要用符」**（`AutoPlayWantAmulet()`）：
   正在打怪时主攻的**灵魂火符**要符，没打怪时补**幽灵盾 / 神圣战甲术 / 隐身术 / 召唤**也都要符，
   任一条成立就把符换回护身符位；槽里已经是符就直接跳过；
4. **两种都不需要时保持现状**；
5. **黄/灰毒粉交替**：一次换毒就是一次使用，下一次换成**另一种**；目标「只缺一种」时直接用缺的那种，
   不会为了交替而装错颜色；
6. **不丢东西、不空转**：背包里没有对应物品就不换（绝不会把槽里的东西卸下来）；
   背包里连一个能用的毒粉都没有时，退回按「需要符纸的技能」处理（不然会一直空着毒槽，
   连灵魂火符都放不出来）；
7. **实际节奏**：开打时「装黄毒粉 → 放施毒术 → 装灰毒粉 → 放施毒术 → 换回符」，
   之后一直挂着符丢灵魂火符。每次只有**状态真的变了**才换一次装（换装后 700ms 节流），
   同一件物品 2 秒内不重复发包（防止本地状态还没同步回来时反复请求）。

配套的施毒节奏（`AutoPlayNeedPoison()`，与服务端道士英雄 AI 一致）：
只有「装备槽里当前那种毒」是目标身上缺的，才放施毒术；否则退回灵魂火符。

> 换毒粉需要**背包里有毒粉**（Shape 1/2 的护身符类物品），且施毒术要**已学会**。
> 槽里的符/毒粉直接看得见，所以不再往聊天窗刷「内挂换毒/换符」提示。

## 三、服务器端开关：免蜡 / 穿人 / 免助跑 / 超负重 / 泰山

### 3.1 服务器配置

`Server/Settings.cs` 的 `Optional` 段：

```ini
EnableNoLamp=True          ; 是否允许客户端使用免蜡
EnableWalkThrough=True     ; 是否允许客户端使用穿人（含穿怪、穿 NPC）
EnableOverWeight=True      ; 是否允许客户端使用超负重
EnableMountTai=True        ; 是否允许客户端使用泰山（被攻击不后仰）
```

若某项为 `False`，客户端面板对应项会置灰，强行点选会被服务器拒绝并回执提示。
免助跑没有配置项，服务器始终放行（纯移动便利开关，不改变任何战斗数值）。

### 3.2 免蜡

`Client/MirScenes/GameScene.cs` 的光照绘制条件改为：

```csharp
if (blinded || (setting != LightSetting.Day && !Settings.NoLamp))
    DrawLights(setting);
```

即：开启免蜡后，夜晚 / 洞穴不再渲染黑暗遮罩（失明毒状态依然生效）。

### 3.3 穿人（含穿怪 / 穿 NPC）

阻挡判定要在**服务端与客户端同时放行**：客户端先判 `EmptyCell()`，不通过就根本不会发起移动，
服务端放行也无效；反过来只有客户端放行则会被服务端拉回。

`Server/MirObjects/HumanObject.cs` 的 `Walk()` / `Run()` 单元格遍历中，跳过以下对象的阻挡：

```csharp
if (WalkThrough && (ob.Race == ObjectType.Player || ob.Race == ObjectType.Hero
                    || ob.Race == ObjectType.Monster || ob.Race == ObjectType.Merchant)) continue;
```

`Client/MirScenes/GameScene.cs` 的 `EmptyCell()` 对应放行：

```csharp
if (Settings.WalkThrough && ob != User && (ob is PlayerObject || ob is MonsterObject || ob is NPCObject))
    continue;
```

（客户端 `HeroObject : PlayerObject`，所以英雄由 `PlayerObject` 分支覆盖；NPC 对应 `ObjectType.Merchant`。）

**地形、门、障碍物、陷阱依然阻挡**，只放行其它玩家、英雄、怪物和 NPC。

### 3.4 免助跑

见 `HumanObject.CanRun`：`(_stepCounter > 0 || FastRun || NoRunUp)`，
即无需先走一步就能直接起跑。服务器始终放行，客户端由 `Settings.NoRunUp` 生效。

### 3.5 超负重

把「负重超限」带来的三类限制一起解除，服务端与客户端成对放行，避免拉回：

| 位置 | 原本限制 | 开启后 |
|---|---|---|
| `HumanObject.CanRun` | 背包超重时不能奔跑 | 照常奔跑 |
| `HumanObject.Run()` | 背包超重时被强制降级为走路 | 照常奔跑 |
| `HumanObject.CanEquipItem` | 腕力负重 / 装备负重超限不能穿戴 | 不再校验 |
| `PlayerObject` 转移到英雄背包 | 英雄背包超重时拒绝 | 不再校验 |
| `Client/GameScene.CanRun` | 同上（客户端预判） | 不再拦截 |
| `Client/MirItemCell` 装备 / 英雄背包 | 同上（客户端预判） | 不再拦截 |

统一由一个虚属性控制，便于英雄跟随主人：

```csharp
// Server/MirObjects/HumanObject.cs
public virtual bool IgnoreWeight => OverWeight;

// Server/MirObjects/HeroObject.cs
public override bool IgnoreWeight => OverWeight || (Owner != null && Owner.OverWeight);
```

**注意**：本服务端「拾取」本来就不校验负重（`HumanObject.CanGainItem` 只看背包空格），
所以超负重主要解决的是「超重后只能走不能跑」「超重后穿不上装备」这两件事。
界面上的剩余负重会显示成负数、负重条满格，属正常表现。

### 3.6 泰山（被攻击不后仰）

服务器被击时会给本人下发 `S.Struck`、给周围广播 `S.ObjectStruck`。
客户端处理 `S.Struck`（`GameScene.Struck()`）时原本会做三件事：

1. `NextRunTime = CMain.Time + 2500` —— 2.5 秒内无法奔跑；
2. `User.ClearMagic()` —— 打断当前施法；
3. 往 `User.ActionFeed` 压入 `MirAction.被击动作` —— 就是俗称的「昂头 / 后仰」。

开启泰和后直接跳过这三步（`if (Settings.MountTai) return;`），角色保持原有动作继续跑 / 继续打。
**伤害结算、麻痹中毒等负面效果完全不受影响**，服务器也照常广播受击给其他玩家
（别人看你仍会正常后仰，只有自己客户端不再播放）。

### 3.7 反作弊设计

开关状态**由服务器持有**，客户端只是「申请」：

1. 客户端 `RequestPlayerOption(option, value)` 发送 `C.SetPlayerOption`。
2. 服务器 `MirConnection.SetPlayerOption()` 按 `Settings.Enable*` 逐项裁决是否放行。
3. 服务器回执 `S.PlayerOption { Option, Allowed, Value }`，客户端以回执为准刷新 UI 与 `Settings`。

因此玩家无法通过改本地配置强行获得免蜡 / 穿人 / 超负重 / 泰山。
进入游戏时（`Server/MirObjects/PlayerObject.cs` 的 `StartGameSuccess()`）服务器会一次性下发全部开关，
保证 UI 与服务器一致；客户端随后按本地偏好自动重新申请（见 2.3）。

## 2. 编译与部署

### 2.1 编译环境

- .NET SDK **8.0.425**，本机路径 `C:\Users\86191\.dotnet\`（需设 `DOTNET_ROOT=C:\Users\86191\.dotnet`）。
- 解决方案：`D:\mir2-20241027\Legend of Mir.sln`。

### 2.2 ⚠️ 编译产物路径（重要，非常容易踩坑）

| 工程 | 产物 | 输出位置 |
|------|------|----------|
| `Server.MirForms\Server.csproj` | **Server.exe / Server.dll** | `Build\Server\Release\` |
| `Server\Server.Library.csproj` | Server.Library.dll | **`Server\bin\Release\`**（无 BaseOutputPath！） |
| `Client\Client.csproj` | Client.exe / Client.dll | `Build\Client\Release\` |

- **只编译 Server.Library.csproj 不会更新 `Build\Server\Release\`**。游戏逻辑全在 Server.Library.dll，必须编译 `Server.MirForms\Server.csproj`（它会连带把 Server.Library.dll / Shared.dll 带过去）。
- Server.exe / Server.dll 是外壳，只有 Library 源码变化时 exe 时间戳不动属**正常增量**，用 Library.dll 的时间戳判断是否更新。
- 两端**不能并行编译**（会撞 NuGet 缓存锁报"当文件已存在时，无法创建该文件"），需串行。

### 2.3 部署

- **服务端运行目录**：`D:\123`（MapPath=Maps，613 张地图；DropPath=Envir\Drops）
- **客户端运行目录**：`D:\微端`（微端模式，Map 下只保留需要的地图）
- 部署前备份旧产物；服务端与客户端涉及协议的改动**必须两端同时部署**（见 §15）。

### 2.4 ⚠️ GBK 编码事故教训（改代码必读）

仓库中存在若干 **GBK 无 BOM** 的 .cs 文件（典型：`Server\Utils\HttpService.cs`）。用文本工具直接改 GBK 文件会把整文件中文永久损坏（变成 U+FFFD）。

**规则**：改任何 .cs 前先检测编码——
- UTF-8 解码成功但含 `\ufffd` = 已损坏；
- UTF-8 解码失败 + GBK 解码成功 = 正常 GBK，**禁止用 Edit 工具直接改**，必须走 python 按 GBK 读、UTF-8-BOM 写回的转码路径（转换后不会再坏）。
- GBK 文件内新增注释一律用英文，防编码污染。

## 3. 运行环境与配置

### 3.1 服务端配置（Settings / Configs）

- `[Network] ResourceMaxKBps`：微端资源下载全局限速（KB/s），**0=不限速**。1Mbps 出口带宽建议 64。详见《微端下载限速说明.md》。
- `Settings.TimeOut`：服务端连接超时，本版已 **10000 → 60000ms**（网络抖动 1 分钟内不误踢）。
- `Configs\BaseStats<职业>.ini`：五职业基础成长（Health/Mana/Weight/Stat 四类公式），改后重启生效。
- `Configs/BuffSystem.ini`、`Configs/OrbsExpList.ini`（弓手气珠经验）等。

### 3.2 客户端配置（Mir2Config.ini）

- `[Game] DropConfirm`：**False = 丢弃数量为 1 的物品不再弹确认框**（默认 True）。数量 >1 的丢弃仍会弹数量框。
- `[Launcher] Browser` / `[MicroClient] Host`：注意地址端口格式，曾出现 `127.0.0.18888` 少冒号导致启动器白屏。
- `[Launcher] Host`：补丁站地址，`[MicroClient] Host`：服务端资源 HTTP 端口（默认 5679）。

### 3.3 数据库

- `Server.MirDB`：启动全量读、关闭全量重写。**运行中改库会被内存旧值覆盖，"停服再改"是唯一可靠顺序**。
- `Envir\`：脚本、掉落表（`Envir\Drops\<怪物名>.txt`，UTF-8 编码，GBK 会全部匹配失败）。

## 4. 核心玩法系统

> 五职业成长公式、122 技能表、属性结算链路、套装系统详见《职业-技能-装备体系详解.md》；弓箭手详见《弓箭手伤害体系分析.md》。此处只列关键结论。

### 4.1 属性与伤害结算

- 属性汇总链：等级 → 装备 → 套装 → 天龙 → 被动 → Buff → 百分比放大 → Caps 截断 → 攻速（`HumanObject.RefreshStats`）。
- 物理攻击：幸运 ±10 = 概率取上下限；防御是减法（armour ≥ damage 即 Miss）；暴击率 = 暴击倍率×5%，暴击伤害 = 暴击伤害/50×10%。
- 攻速：`1400 - (攻速×60 + min(370, 等级×14))`，下限 550ms。
- 弓箭手技能伤害吃 **MC（魔法）**，结算走 MAC；普攻 DC + 距离衰减。精神状态：0 集中=100%、1 穿透=55%+5%×等级、2 组队=80%。
- **已知原版缺陷**：`CanEquipItem` 的职业校验 switch 没有 `case MirClass.弓箭手` 分支 → 弓手不校验装备 RequiredClass（未修）。

### 4.2 技能冷却（已修复）

- 修复点：`MagicInfo.GetDelay()` 原 `DelayBase - Level×DelayReduction` 全程 **uint 运算**，减出负数时回绕成 ≈49.7 天。已改 long 运算并夹 0。
- 运行时以 `Server.MirDB` 中技能数据为准：`FillMagicInfoList` 对已有技能 `MagicExists` 直接跳过，**改代码里的默认值不生效，必须改库**（停服改）。
- 已知高风险配置：`月影雾-秘籍`、`血龙兽-秘籍`（Base < Reduction，旧 DLL 下 Lv2 起冷却 49.7 天）。数据侧建议 月影雾 设 `DelayBase=16000, DelayReduction=0`。

### 4.3 万效符（灵魂火符·升级版）

- 副目标以**施法者**为圆心取范围（原版错以主目标为圆心、半径仅 2 格），`SoulFireBallPlusSpreadSize=13`。
- SoulFireBall / SoulFireBallPlus / SoulFireBallPlusRare 的 Range 已 9 → 13。
- 无目标时静默返回不再提示"请先选择一个可攻击的目标"（`FindObject` 半径已随 castRange 联动）。

### 4.4 掉落系统

- 配置：`Envir\Drops\<怪物名>.txt`，入口 `Envir.ReloadDrops`。
- 格式约束：Chance 必须是 `1/N` 严格格式（`10/100` 两位分子**解析失败**）；分组 `GROUP` / `GROUP*`(随机) / `GROUP^`(首个) + `{}` 块；`#INSERT [子文件]` 只展开一层，文件不存在会**崩掉整个 ReloadDrops**。
- 物品名匹配只忽略大小写并去掉数据库侧空格；文件必须是 UTF-8（GBK 中文物品名全部匹配失败）。
- 失败输出在 MessageQueue：「未能加载 \<名\> 所需物品： \<行\>」。

## 5. 英雄系统

### 5.1 魔血石对英雄生效（已修复）

- `ProcessStones` / `ConsumeStoneDura` / `NeedStoneHeal` / `RemoveStone` 从 PlayerObject **下沉到 HumanObject**（均保持 virtual），英雄与玩家共用同一套魔血石逻辑。
- 需重启服务端生效。英雄石头耗尽提示无客户端显示（ReceiveChat 对英雄为空实现，无害）。

### 5.2 英雄 AI（智能化改造）

核心行为（均服务端逻辑，重启生效）：

1. **集火主人目标**：`FindTarget` 开头优先选中 `Owner.Target`，配合主人输出。
2. **被围自动群攻**（基类 `SurroundedCount` 属性）：
   - 战士：被围(≥2敌)优先 剑刃雪崩(正面3格) → 半月/圆月；
   - 刺客：优先 月华乱舞(360°)，没学且被 3+ 围死才脱围；
   - 道士：优先 毒云(需毒粉)，没学/没毒粉被围脱围；
   - 弓手：优先 火雨箭(无道具需求)；
   - 法师：原有群攻体系 + 贴身自动后撤。
   - **脱围**：完全没群攻且被 3+ 围死时执行，脱围前先清 `NextMagicSpell`（否则法术队列卡死英雄永远不放技能）。
3. **远攻风筝**：法师/道士 dist==1 且有远程法术时先施放**再**走位（防法术队列活锁）；走位用 8 方向评分：
   `得分 = 离威胁距离×10 − 落点周围1格敌数×20 + 背向加成5`，全堵退回背向。
4. **自动捡药补给**（`ProcessSupply`）：AutoPot 开启且对应药水耗尽时，用**有界 A\* 寻路**（`Server\MirObjects\PathFinder.cs`：MaxNodes 300 / 范围 12 格 / 直10斜14 / 禁斜穿墙角）走向视野内同类地面药水拾取；路径缓存每 tick 走一步，失败直线兜底。金币/不匹配药水不捡；捡药期间 roaming 不拉扯。
5. **空闲预增益**：五职业空闲（InSafeZone 守卫）时对自身放增益技能。

**已知限制**：
- 英雄背包**不实时刷新**到客户端：捡到药后需重召唤英雄或重登才能看到；功能本身（喝药）即时生效。
- 英雄装备面板无增量协议，穿戴后同样需重召唤/重登显示。

### 5.3 英雄技能书

英雄与主人**同一套**技能书：同 ItemType.技能书 / Shape 映射 / RequiredClass 职业限制 / 等级限制 / 防重复。英雄自己使用书学习。

### 5.4 技能升级机制（常见误解）

`LevelMagic` 只在**使用技能的瞬间**判定，没有定期检查。改了技能经验/人物等级后，让英雄**使用一次该技能**即会升级。若经验早已超出但一直不用，就一直不升——这是原版设计，不是 bug。

## 6. NPC 脚本扩展命令

> 脚本位于 `Envir\NPCs\`，`00Default.txt` 为全局默认段。以下为本版新增。

### 6.1 条件：HEROLEVEL

```
#IF
HEROLEVEL < 50
#SAY ...
```

- 判定当前英雄等级，镜像 LEVEL 实现，支持标准比较运算符。
- 英雄未召唤 / 已死亡时条件**不成立**。

### 6.2 动作：GIVEHEROEXP

```
#ACT
GIVEHEROEXP 6000
```

- 直接给英雄加经验。原 GIVEEXP 走玩家 GainExp，**英雄拿不到**，本命令补齐。
- 英雄未召唤/死亡时静默跳过；不受 ExpRate 影响，但受英雄 `Stat.经验增长数率` 加成。

### 6.3 动作：EQUIPITEM / HEROEQUIPITEM

```
#ACT
EQUIPITEM 圣战头盔
HEROEQUIPITEM 圣战头盔
```

- **凭空创建**指定物品并直接穿到玩家/英雄身上（不进背包）。
- 共用 NpcEquip 实现：GetItemInfo → CreateFreshItem → CanEquipItem 校验 → BindOnEquip 绑定 → 槽位刷新。
- 部位被占时**拒绝**不覆盖；物品不存在时脚本告警。
- 英雄侧推 NewHeroInfo + RefreshStats，功能即时生效，但面板显示需重召唤/重登。

### 6.4 动作：REPAIR

```
#ACT
REPAIR <部位> [special]
```

- 按槽位修理装备，14 槽全覆盖；带 `special` 参数时不损耐久上限。
- 引擎内没有"一键修全身"，要全身修理需脚本逐槽写 REPAIR。

### 6.5 配套循环/判定命令（原版已有，泡点脚本依赖）

| 命令 | 说明 |
|------|------|
| `SETLOOPTIMER <秒> <label>` | 定时循环触发 NPC 段，最小 1 秒 |
| `EXPIRETIMER` | 结束当前循环定时器 |
| `CHECKMAP <地图名>` | 判断玩家所在地图（按 FileName 匹配） |
| `CHECKRANGE <x> <y> <范围>` | 判断玩家与坐标距离（仅当前地图有效） |
| `GIVEEXP <n>` | 给玩家经验（英雄不跟随） |

> 注意：脚本条件体系**没有 NOT**。需要"否则"逻辑时用路由技巧（见 §7 示范）。

## 7. 泡点脚本

### 7.2 泡点-玩家英雄分段经验.txt（0 图 329,268 半径 10）

## 9. 商城系统

### 9.1 机制

- 数据：`Envir.GameShopList`（存于 Server.MirDB），由管理端 `Database\GameShop` 窗体录入；双货币 GoldPrice / CreditPrice。
- 商城列表在**登录时一次性下发**（`GetGameShop`）；客户端静态缓存只增不清——因此历史版本重载后在线玩家永远看旧数据。

### 9.2 本版修复

1. **购买崩溃（KeyNotFoundException key '120'）**：原版键错位 bug——读/发包全用 `Product.Info.Index`（物品ID），唯购买写入 4 处错用 `Product.GIndex`（商城格位）。GIndex ≠ Info.Index 的商品第二次购买必炸。已统一 4 处写入键为 `Info.Index`。历史残留错误键条目无人读、随档存盘、无害。
2. **重载在线生效**：`S.GameShopInfo` 包尾追加 `bool Reset` 字段（向前兼容旧客户端），客户端收到 Reset=true 清空本地缓存再收全量。

### 9.3 商城重载不生效排查顺序

1. 商城编辑窗体**关了没有**？（不关不存 DB）
2. 用的是 @RELOADGAMESHOP 吗？（旧版重载命令不会推送在线玩家）
3. 客户端是否旧版（不认 Reset 字段）？→ 重登一次即可看到新数据。

## 10. 网络稳定性与断线优化

### 10.1 短时断线不踢人（本版核心改动）

| 项 | 改动 | 效果 |
|----|------|------|
| 服务端超时 | Settings.TimeOut 10s → **60s** | 抖动 1 分钟内不误踢；服务器程序不重启，网络恢复后客户端可继续连 |
| 客户端断线处理 | Network.cs 不再 `Program.Form.Close()` 退出程序 | 游戏内断线弹框，点确定回登录界面（ReturnToLoginOnDisconnect），可直接重连 |
| 客户端心跳 | **保持 60 秒不动**（用户明确要求，30 秒改动已回滚） | — |
| 战斗退出等待 | GameScene.LogOut 的 10 秒 LogTime 分支**两端同步注释**（客户端弹框逻辑 + 服务端拦截） | 战斗中可立即退出确认 |

> 部署提醒：超时改动需部署 Server；断线回登录需部署 Client；战斗退出需两端同时。

### 10.2 微端下载限速（防下载抢带宽导致一步一卡）

- 服务端 `HttpService.WriteFileStream` 加**令牌桶**全局限速；传输超时按限速自适应推算。
- 配置：`[Network] ResourceMaxKBps`（0=不限）。1Mbps 出口建议 **64**。
- 客户端：紧急队列——切图缺资源时 `EnsureLocalFileBlocking` 会把该文件**插队优先下载**，减少原地卡顿。
- 细节见《微端下载限速说明.md》。

## 11. 微端与补丁分发

### 11.1 PList.gz 清单

- 名字带 .gz 但内容**未压缩**；格式 = `int32 count` + 每条 `7bit长度+UTF8文件名 / int32 Length / int32 Compressed / int64 时间`。
- 本版追加 **MD5 段**（`int32 0x3135444D "MD51"` + count×16B，**追加在旧格式末尾**）：旧版更新器读到 count 条即停，完全向后兼容。
- 工具：`Tools\plist_decode.py`（查看/--check 对照本地/--csv 导出/--build 重建清单）。

### 11.2 客户端下载健壮性（本版修复）

- `.gz` 请求仅在 `Compressed>0 && !=Length` 时发起（旧版把 Compressed=0 误判为"需压缩"，去拉不存在的 .gz，nginx 404 的 153 字节 HTML 被写成 `Map\0.map` → **进图黑屏**，已实际发生过）。
- 请求失败带 .gz 时退回原名重试；非 2xx 状态码**直接拒写盘**记 Error.txt；ContentLength 与实际不符拒写；下载后按清单 MD5 校验，不符不落盘。
- `CheckFile` 在大小+时间一致时再比本地 MD5，能检出静默损坏的文件并重下。
- **启用 MD5 校验**需用新版 AutoPatcherAdmin 点「更新列表」重建 PList.gz；现有旧格式清单客户端也能正常下载。

### 11.3 微端资源服务

- 服务端自写 HTTP（默认端口 5679，`/resource?f=路径`），目录白名单 data/ map/ sound/ directx/ localization/（防穿越已做）。
- `Settings.ResourcePath` 指向的 ClientResources 目录**必须存在且放齐文件**，缺文件时请求落到外部 nginx 会返回 404 HTML（黑屏事故根因之一）。
- 微端 `ResourceDownloader.Ensure`：本地文件存在就不重下——手工替换微端文件不会被自动覆盖，但也不会自动更新。

### 11.4 客户端/服务端地图文件规则（钓场改动得出）

- 服务端 `Maps\0.map` 与客户端 `Map\0.map` **图块资源不同，不能整文件互拷**；只能逐格同步 light 字节。
- 客户端微端有 `if (File.Exists) return true` 逻辑，本地文件存在不会重下；改图后要么改微端本地文件，要么重建 PList 强制重下。

## 16. 常见问题 FAQ

**Q1：改了代码/配置为什么不生效？**
按顺序排查：① 是否编译了对的工程（Library 要经 Server.MirForms 编译才会进 Build\Server\Release）；② 产物是否部署到运行目录（D:\123 / D:\微端）；③ 是否重启服务端（MirDB/脚本/地图多数要重启，NPC/商城有热重载命令）；④ MirDB 类改动是否在运行中改库（会被内存覆盖，必须停服改）。

**Q2：技能经验够了为什么不升级？**
LevelMagic 只在使用技能瞬间判定。人物等级达标后**用一次技能**即升。

**Q3：商城重载后玩家看到的还是旧数据？**
① 商城编辑窗体没关（不关不存 DB）；② 客户端没更新到带 Reset 的版本 → 重登一次。

**Q4：商城购买报 KeyNotFoundException '120'？**
旧版 DLL 的键错位 bug，换新版 Server.Library.dll 即修。

**Q5：网络一抖就掉线？**
部署新版 Server（TimeOut 60s）+ 新版 Client（断线回登录界面）。掉线后服务器不重启即可直接重连。

**Q6：下载资源时游戏一步一卡？**
设 `[Network] ResourceMaxKBps=64`（1Mbps 带宽参考值），并确认部署了限速版服务端。

**Q7：进图黑屏/卡死？**
查 `Map\0.map` 是否被写成 HTML（用记事本开头顶部是否 `<html>`）；查补丁站是否返回了 404（`补丁诊断.exe --all`）；确认微端本地文件完整。

**Q8：灵魂火符提示"请先选择目标"但不飞？**
旧版 DLL 的 FindObject 半径 10 与射程 13 不匹配，换新版即修。

**Q9：英雄捡了药背包没显示？**
英雄背包不实时同步（原版无增量协议），重召唤英雄或重登即同步，功能不受影响。

**Q10：冷却显示几百万秒？**
旧 DLL uint 下溢 + DB 里 Base<Reduction 的技能。换新 DLL 修复显示；数据侧建议把 月影雾-秘籍 改 `DelayBase=16000, Reduction=0`（停服改库）。

**Q11：钓不了鱼？**
先查站位：钓点在身前第 3 格，站远点对着水按 N；查身上是不是 Shape 49/50 的鱼竿；查所在格子 light 是否 100~119（用 `map_fishing_scan.py` 或钓场编辑器查看）。

**Q12：泡点脚本怎么改成别的地图/数值？**
复制 `泡点-玩家英雄分段经验.txt`，改 CHECKMAP 地图名、CHECKRANGE 坐标半径、各 GIVEEXP/GIVEHEROEXP 数值即可；保留"英雄没吃到经验才进结束检查"的路由结构（§7.2）。
